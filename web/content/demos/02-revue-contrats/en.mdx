architecture:
  alt: "Architecture: the Lambda function runs full-text and vector search in parallel in Aurora (pgvector), merges and reranks the results, has the answer drafted, then submits it to a judge model before showing it."
  choices:
    - title: Hybrid search (keywords + vectors)
      why: The exact terms of a contract ("indemnification", party names, clause numbers) are poorly matched by vectors alone.
    - title: Reranking
      why: A specialised model pushes the truly relevant clauses to the top of the first 50 candidates.
    - title: Faithfulness check before display
      why: An answer that the cited clauses don't support is blocked or rewritten, and its score is shown.
    - title: Aurora Serverless v2 that sleeps, queried through the Data API
      why: The database pauses when nobody uses it; the Data API avoids putting the Lambda function in a private network (and paying for the NAT Gateway that comes with it).
  discarded:
    - title: Vectors only
      why: Misses too many clauses referred to by their exact wording.
    - title: Trusting the model without a check
      why: Unacceptable for legal work, even with good citations.

  alt: "Pipeline: contracts on S3, Step Functions extracts the text, splits it by clause with metadata, computes embeddings and writes to Aurora (pgvector and full-text index)."

Quality comes from three complementary layers: hybrid search that doesn't miss exact terms, reranking that sorts the candidates, and a faithfulness check that won't let an unsupported claim through.
