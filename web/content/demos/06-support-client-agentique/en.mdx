architecture:
  alt: "Architecture: a LangGraph agent in a Lambda function routes the question to help-centre search (S3 Vectors), a catalogue or order tool (DynamoDB), a request for details, or an escalation; it grades what it finds, tries again if needed, and goes through Bedrock Guardrails before answering."
  choices:
    - title: An explicit agent graph (LangGraph)
      why: Every step and transition is visible and testable, unlike a free-roaming agent.
    - title: Grade before answering (Corrective RAG)
      why: If the passages found don't answer the question, the agent rephrases or stops instead of making things up.
    - title: Bedrock Guardrails
      why: Denied topics, personal data filtering and ungrounded-answer detection, configured rather than coded.
    - title: A swappable second model provider
      why: "Many companies mandate OpenAI; the agent runs on Claude via Bedrock or on OpenAI, through configuration alone."
  discarded:
    - title: Simple RAG over the FAQ
      why: It can neither look up an order nor decide to hand over.
    - title: An agent without a graph, choosing its tools freely
      why: Hard to predict and test; not suited to customer contact.

The point isn't to answer everything, but to know when not to. The agent is built as an explicit graph, tested on scenarios, with a human handover designed in from the start.
